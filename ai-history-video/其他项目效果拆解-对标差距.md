# 其他项目效果拆解：我们这支 vs talkcraft / anything2explainer

> 拆解对象：video-talkcraft（108 张动效卡，含在线画廊逐卡可播）、anything2explainer 的 `reference/motion-vocabulary.md`、`narration-storyboard.md`（量化规范原文）。结论：差距不在画风，在**时间系统**。

## 一、他们的效果强在哪（7 条，全部可量化）

### 1. 时间锚点：元素出现帧 = 字幕块起始帧，容差 −6…+3 帧
- anything2explainer：旁白用 `｜` 切成 ≤16 字字幕块，**逐句（甚至逐块）合成 TTS + WordBoundary**，每块起止帧精确已知。元素入场对齐块首帧，不是"大概这个时间"。
- talkcraft：本机 CPU 字级对齐（FireRedASR2-CTC），实测字级偏差中位 **20–40ms**、最差 200ms，"每个动效节拍都锚在确切的字上"。
- 停顿也是设计过的：段内句间 10 帧、段末 30 帧、章前 45 帧。

### 2. 镜头 ≠ 句子：镜头按"画面单元"分，单镜头 ≥120 帧
- 2–4 句 = 一段 = 一个镜头；短句（<3s）并入相邻镜头当节拍，不单独入场+离场。
- 所以他们的画面是"一个世界在演"，元素**承接**到下一镜头（同组件同参数缩小移位让位），不是每章换一页 PPT。

### 3. 每镜头一个主角（Hero），且有尺寸下限
- 主角：图形 ≥170px 或大字 ≥96px，第 1–2 个节拍入场，带常亮柔光 + 呼吸；配角不发光。
- 一帧内：主角光 1 处 + 重点光 ≤1 处；光只有紫/橙/红三色。

### 4. 动效是"词汇表"，每个动作有帧数
SoftIn 8 帧 / GlitchIn 12 帧（重点词，每镜头 ≤1 处）/ 滑入 18–22 帧 / 错峰 2 帧/个 / draw-on 线 16–28 帧 / 计数 14–26 帧 / 强调脉冲 30 帧（峰值 1.11）/ 高亮条 wipe 12 帧。
入场比出场用力（talkcraft：入场 0.2–0.8s，出场 0.15–0.5s）；离场必须先归零再硬切（末帧残留 >20% 可见度算事故）。

### 5. 运镜有预算：每章 ≥3 次
推近 30–40 帧（1→1.33）、拉远 37–45 帧、承接位移 16 帧、整组平移/滚动、视差分层。
运镜不进末拍：推完必须停 1–1.5s 再离场；HUD/字幕在屏幕空间不动，只动内容层。

### 6. "持续动作"：静止 >3 秒 = 缺陷，但禁止假呼吸
每句解说至少一处可察觉变化；没有新元素时用一次 30 帧推近替代。
持续动作必须是语义动作：数据流沿箭头跑、逐行打字、逐格点亮、曲线生长——不给静止物体加漂浮/呼吸凑数。

### 7. talkcraft 的 108 张卡：按"这一句是什么"选，不是按好看选
7 大类：字幕花字 / 强调标注 / 数据信息图 / 素材呈现 / 转场结构 / 人物互动 / 运镜。
与 AI 发展史最相关的：`line-chart-story-draw`（折线分段推演）、`number-counter`（数字滚动）、`step-timeline-vertical`、`chart-grow`、`chat-message-flow`（聊天自演）、`typewriter-reveal`、`focus-dim-spotlight`（讲到哪哪亮，其余压暗 40%）、`chapter-progress-list`。
纪律：同一时刻同屏重音只能有一个；每卡入场→hold→出场三段式，节奏命门固定、文案/颜色参数化。

## 二、我们 v1 的差距（逐条对照）

| # | 他们 | 我们 v1 |
|---|---|---|
| 时间锚点 | 字/块级时间戳，入场容差 −6…+3 帧 | 3 张卡按固定 0.7s+0.55s 间隔入场，和旁白内容无关 → **用户说的"没卡上"** |
| 镜头单位 | 一段（2–4 句）一镜头，元素承接过镜 | 一章 = 一页静态版式 20 多秒，就是 PPT 翻页 |
| 主角 | 每镜头 1 个 Hero ≥170px 带光 | 右侧小图标 ~300px 内缩着，左侧三张同字号卡片，无主次 |
| 持续动作 | 每句必有语义动作 | 图标入场后基本静止，只有星星闪 |
| 运镜 | 每章 ≥3 次有目的的推拉 | 完全静止机位 |
| 强调 | 脉冲/变色/高亮条锚在重音字上 | 无强调系统，讲到数字时数字没有任何反应 |
| 转场 | 离场归零 + 承接位移 + 章界承接 | 整页淡入淡出 |
| 数字呈现 | Counter 滚动、图表逐段生长 | "两个月破亿"只是卡片上一行字 |

## 三、结论：不要在 v1 上打补丁，要换时间系统（3 步）

1. **逐句合成配音**（anything2explainer 的 kokoro 路径同理）：把旁白按句/块切开逐条合成，每块时长采样级精确 → 拍边界不需要 ASR 猜，天然帧准。这一步我们立刻能做（配音工具按条出音频）。
2. **先写 SHOTBOOK 再写代码**：每镜头一行——帧区间、每拍字幕块起始帧、画面主角（唯一）、入场动作+对齐哪一拍、持续动作、运镜、离场方式。没有分镜表不写渲染代码。
3. **引擎换 Remotion 或按词汇表重写**：Pillow 引擎缺缓动/光效/相机系统，硬堆会越来越慢；若继续 Pillow，必须先把 SoftIn/计数/draw-on/推镜/承接这套词汇做成函数库，再按 SHOTBOOK 逐镜头实现，而不是一章一个通用模板。

> 一句话：他们是"**解说词驱动的电影**"，我们做的是"**配了音的 PPT**"。差的第一性原理是：他们的每一帧都知道现在说到哪个字，我们的每一帧只知道现在是第几秒。
